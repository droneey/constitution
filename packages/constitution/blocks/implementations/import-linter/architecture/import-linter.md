# import-linter

> The template's contracts hold core's layer matrix by the folders of core's tree: what `kernel/`, `libs/`, `shared/` and a feature's `domain/` may not import; features, modules of composition, adapters, entrypoints and integrations blind to each other; adapters kept from their callers; a binding unit kept from the ports of its domain; `root/` imported only by the entry files, and no entrypoint or integration imported at all; `composition/` imported by none of the layers below it; reads and writes apart; the effect modules of the standard library out of every layer below the edge, through a lib as well — a vendor's package a lib wraps is left to a reviewer; no layer folder's `__init__.py` imported; and a role folder of the kernel, and a module of each layer from outside it, reached only through their `__init__.py` — a contract matches its importers by wildcard, so a sibling module that reaches past another's `__init__.py`, or a file that reaches past a role folder's of its own feature, is left to a reviewer. Where a package is imported is held outside these contracts, by core's table and the homes the blocks give; a contract names a module from outside, through `include_external_packages`, only to keep a part of the standard library out of the layers below the edge. Where a file lives and how a folder is laid out no contract shows, and a reviewer holds them.
