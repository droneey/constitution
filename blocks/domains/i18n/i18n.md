# Internationalisation

> Text a person reads, in the language and format of their locale.

## user-facing-text-from-catalog · MUST
Every string a user reads comes from the message catalog, by key; none is written in code.
**Why:** text in code cannot be translated or reworded without a code change, and it is found only by reading every file.
**Check:** review
**Tags:** ux
**Implements:** `one-home-per-datum`

## messages-take-named-parameters · MUST
A message takes its values as named parameters; a sentence is never built by joining strings.
**Why:** languages order words differently, so a sentence joined in code cannot be translated.
**Check:** review
**Tags:** ux

## plural-forms-by-locale-rules · MUST
Plural and ordinal forms come from the locale's CLDR rules, inside the message, never from a condition in code such as "the count is one".
**Why:** many languages have more than two plural forms, and code written for one language gets the others wrong.
**Check:** review
**Tags:** ux

## locale-reachable-without-props · SHOULD
The current locale is reachable anywhere in the presentation without being passed as a prop.
**Why:** a locale threaded through every component couples all of them to it.
**Check:** review
**Tags:** architecture

## domain-returns-codes-not-text · SHOULD
Domain and application code return codes and values, and the presentation turns them into text; the message library never reaches the domain.
**Why:** the domain stays free of any language, and one code is worded differently per screen and locale.
**Check:** tool — architecture
**Tags:** architecture
**Implements:** `domain-imports-only-itself-and-kernel`

## values-formatted-by-locale · SHOULD
Numbers, dates, currencies and lists are formatted by the locale.
**Why:** `1,000.50` and `1.000,50` are the same number to different readers; a fixed format misleads one of them.
**Check:** review
**Tags:** ux

## Requirements for implementation

What any message library must provide.

## i18n-plurals-by-cldr · MUST
Plural and ordinal forms are selected by CLDR data.
**Why:** without it, plural forms cannot follow the locale's rules.
**Check:** review
**Tags:** ux

## i18n-parameters-without-concatenation · MUST
A message takes named parameters inside it.
**Why:** without it, sentences are joined in code.
**Check:** review
**Tags:** ux

## i18n-typed-keys · SHOULD
A missing or misspelt key fails the check.
**Why:** a missing key shows the user a raw key instead of text, and only a check finds it before they do.
**Check:** review
**Tags:** ux

## i18n-lazy-locales · SHOULD
Each locale's catalog loads on demand.
**Why:** a user downloads only the language they read.
**Check:** review
**Tags:** performance
