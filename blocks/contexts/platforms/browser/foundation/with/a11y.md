# Browser with accessibility

> The mechanisms that meet the accessibility outcomes in HTML.

## native-html-elements-first · MUST
`<button>` for an action, `<a href>` for a move, lists as lists, tables with headers and a caption; ARIA only where HTML has no element.
**Why:** a native element brings its role, its keyboard and its announcement; ARIA on a generic element brings only a promise.
**Check:** tool — lint
**Tags:** a11y
**Implements:** `native-semantics-first`

## landmarks-and-skip-link · MUST
Every page has landmarks — header, navigation, main, footer — and a link to skip to the content comes first.
**Why:** screen reader and keyboard users jump by landmarks, and the skip link spares them the navigation on every page.
**Check:** test
**Tags:** a11y
**Implements:** `wcag-aa-conformance`

## fields-declare-autocomplete · MUST
A field for the user's own data declares its purpose with `autocomplete`.
**Why:** the browser then fills it in, and assistive technology can tell the user what it is for.
**Check:** tool — lint
**Tags:** a11y, ux
**Implements:** `every-control-has-an-accessible-name`

## live-regions-polite-by-default · MUST
A status goes to a polite live region, and only an urgent error to an assertive one. An invalid field has `aria-invalid` and `aria-describedby` pointing at its message.
**Why:** assertive announcements interrupt what the user is listening to, so they are kept for what cannot wait.
**Check:** review
**Tags:** a11y
**Implements:** `status-changes-announced`

## focus-ring-from-design-system · MUST
The focus ring is the design system's, shown on `:focus-visible`; `outline: none` needs that replacement.
**Why:** one ring looks the same everywhere and is always visible to keyboard users.
**Check:** review
**Tags:** a11y
**Implements:** `focus-always-visible`

## type-sized-in-rem · MUST
Type sizes are in `rem`, text spacing may be overridden by the user, and at 320 CSS pixels content reflows without scrolling sideways.
**Why:** the user's own text size and spacing settings then apply, and a zoomed page stays readable.
**Check:** review
**Tags:** a11y
**Implements:** `wcag-aa-conformance`

## browser-checklist-before-shipping · SHOULD
Before a new interactive component ships: Tab reaches it in visual order, Enter or Space works it, Escape closes a layer, focus returns to its trigger, and a screen reader announces it as it should.
**Why:** these are the checks a scan cannot make, and each takes a minute by hand.
**Check:** review
**Tags:** a11y
**Implements:** `interactive-checked-by-hand`
